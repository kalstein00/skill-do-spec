# Synthetic fixture provenance

Since 0.2.0 `demo` also creates `issues.json`, an explicit mutable fake tracker state store. Markdown files remain immutable requirements. Default completion is issue closed; only explicit legacy `external-checkpoint` uses the old runtime verification/commit gate.

`local/` is authored for this repository, not copied from corporate issues or upstream skill wording. It expresses the explicit Parent / Blocked by / Acceptance criteria sections used by the local parser. `demo` generates equivalent ten-ticket inputs and an isolated Git project at the chosen empty directory.

Use the example only as a mapping reference; actual user variants must supply their own verified artifact contract. Remote operation fixtures are generated by `tests/test_tracker.py`; fake gh/tea protocol is explicitly synthetic.

The editor schema in `schemas/project.schema.json` documents the current local format. Runtime Python validation is authoritative and live profiles remain blocked. PRD features outside this schema remain incomplete, not silently optional.
